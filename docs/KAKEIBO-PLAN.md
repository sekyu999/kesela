## 1. 現状分析

### 今のデータ構造（DB 版5・バックアップ版5）

| テーブル | 中身 | 今回の家計簿との関係 |
|---|---|---|
| categories | 食材・日用品のカテゴリ17種 | **使わない**（家計簿は別のカテゴリを持つ） |
| products | 商品マスタ（在庫・目標在庫・毎日の量・栄養） | 連動しない |
| stores | 店舗 | 家計簿の「どこで買ったか」に任意で使える |
| storeShelfOrders | 店舗ごとの売り場順 | 無関係 |
| shoppingListItems | 買い物リスト | 連動しない |
| priceRecords | 店舗ごとの1つあたり価格（商品×店舗で1件） | 連動しない |
| foodGroups | 食事グループ | 無関係 |
| plans | **既存の「家計」**＝買いたい物・やりたい事（kind/title/price/month/memo/url） | **ここだけ連動する** |
| meta | schemaVersion・profile・note・lastBackupAt・selectedStoreId | 家計簿の設定を足す |

### 今の画面構成

- 下のタブ6つ：**目標 / リスト / 在庫 / 価格 / 食事 / 家計**、設定はヘッダー右の歯車
- 起動時は「目標」のページ（設定でオフ可）。30分以上離れて戻った時も目標へ
- 既存の「家計」(`js/screens/budget.js`) は plans の一覧と、月ごとの見込み（買いたい物・やりたい事の積み上げ棒）だけ。**v1.5 で食費は見込みから外してある**ので、今回の家計簿と二重計上にはならない
- 「食事」タブに1か月の食費の**目安**（毎日食べる物 × 最安価格 × 30日）がある。これは実績ではないので、家計簿の食費実績とは別物として扱う

### 今の作りの決まりごと（守る）

- 素の HTML/CSS/JS、ビルドなし。`screens → data → domain` の一方向依存。domain は純粋関数でテスト対象
- 画面の自動更新は Dexie の `liveQuery`（`js/ui/live.js` の `watch()`）
- 文字は必ず `t('…')` で囲み、`js/i18n/en/*.js` に英訳を書く（`npm test` の i18n-check で漏れが落ちる）
- ファイルを足したら `node tools/release.mjs <版>` で `sw.js` の APP_FILES を作り直す
- 同期（Dexie Cloud）がオンの端末は DB 名 `kesela`、オフは `yuteli`。**新テーブルは両方で同じ定義**にする
- 端末ごとの設定は localStorage（バックアップ・同期の対象外）

### 今回の依頼で引っかかる点（先に潰す）

1. **タブが足りない。** 現在6つで、320px 幅でもう限界。家計簿を足すと7つになるので、必ずどこかを畳む（5章で案を出す）
2. **「食事」タブが優先順位リストに入っていない。** → **今のまま独立タブで残す**（10章 D2）
3. **「家計簿」と既存「家計」は別物だが、タブを分けると混乱する。** 1つのタブの中で「今月（実績）」「予定（見込み）」に分ける案を推す
4. **固定費の自動反映は二重計上の温床。** 4章で方式を決める
5. **「貯金額」「使えるお金」の定義が未確定。** 4章で定義を提案する
6. **ウィジェットは同期（Dexie Cloud）がオンでないと作れない。** Scriptable は端末内の IndexedDB を読めないため、クラウド経由しかない。今のウィジェットも同じ前提

## 2. 新しいデータ構造（DB 版6・バックアップ版6）

新テーブルを4つ足す。既存テーブルへの追加は、**項目を2つ増やすだけ**（既存の値は変えない）。

| 既存テーブル | 足す項目 | 用途 |
|---|---|---|
| stores | `colorIndex`（number） | 店舗の色（11-3・11-4） |
| products | `trackStock`（boolean・既定 true） | 在庫を管理するか（11-5） |

### expenseCategories（家計簿のカテゴリ）

食材の `categories` とは**別物**。売り場順や在庫とは無関係。

| 項目 | 型 | 説明 |
|---|---|---|
| id | string | |
| name | string | 食費、日用品… |
| type | `'expense'` \| `'income'` | 支出用か収入用か |
| colorIndex | number | 円グラフの色（テーマの変数から割り当てるので、テーマを変えても崩れない） |
| defaultOrder | number | 並び順 |

インデックス：`id, type, defaultOrder`

初期カテゴリ（支出）：食費／日用品／住居／水道・光熱／通信／交通／医療・衛生／交際・娯楽／衣服・美容／教養・趣味／サブスク／その他

### transactions（実績＝実際に発生した収入・支出）

| 項目 | 型 | 説明 |
|---|---|---|
| id | string | |
| type | `'expense'` \| `'income'` | |
| amount | number | 円の整数（税込） |
| date | string | `YYYY-MM-DD` |
| categoryId | string | → expenseCategories |
| memo | string | |
| storeId | string \| null | 任意。既存 stores から選べるだけで、価格・在庫とは連動しない |

インデックス：`id, date, categoryId, type, fixedCostId, [date+type]`
月の集計は `date` の範囲検索（`2026-11-01` 〜 `2026-11-31`）で取る。月ごとの合計は保存しない（持つと必ずズレるため、毎回その場で計算する）。

| memo | string | |

インデックス：`id, categoryId`

| 項目 | 型 | 説明 |
|---|---|---|
| id | string | |
| month | string \| null | `YYYY-MM`。**null = 毎月の既定値** |
| categoryId | string \| null | **null = 月全体の予算** |
| amount | number | 円 |

インデックス：`id, month, [month+categoryId]`

毎月設定し直さなくていいように「既定（month = null）」を持ち、その月に上書きがあればそちらを使う。

### meta に足すもの

- `savingsGoal` … 今月ためたい額（円）。任意
- `kakeiboLastGeneratedMonth` … 固定費を自動で入れた最後の月（`YYYY-MM`）

- `DATA_TABLES` / `TABLES` に4テーブルを追加 → バックアップと同期の対象に入る
- `backupFormat.js`：`CURRENT_SCHEMA_VERSION` を 6 に。`MIGRATIONS[6]` は**空配列を足すだけ**（既存データは変換しない）
- `RULES` に4テーブルの検証を追加し、`stores` に `colorIndex`（任意・数値）、`products` に `trackStock`（任意・真偽）を許す

## 3. 既存の「家計」との役割分担と連動

| | 既存の家計（plans） | 新しい家計簿（transactions） |
|---|---|---|
| 性質 | 見込み・計画 | 実績・事実 |
| データ | 買いたい物・やりたい事（名前・金額・月） | 1件ごとの収入・支出（金額・日付・カテゴリ） |
| 変更 | **何も変えない** | 新規 |

### 連動するのは「表示」だけ

データは行き来させない。家計簿の集計結果を使って、予定側に次の2つを足す。

1. **貯金ペース** = 直近3か月の「収入 − 支出」の平均（実績が1か月分もなければ今月の実績、それも0なら非表示）
2. **実現できそうか** = 各予定の月までに貯まる見込み額（今月の余剰 + ペース × 残り月数）と、その月までの予定の累計額を比べて
   - 足りる → 「届きそう」
   - 足りない → 「あと ◯◯円」

買い物リスト・価格・在庫・食材とは**連動させない**。スーパーで食材を買った支出は、家計簿では「食費」の1行として記録するだけ。

### 食費の二重計上について

食事タブの「1か月の食費」は毎日食べる物からの**目安**で、家計簿の食費は**実績**。
名前が似ていて混同するので、食事タブの表示を「食費の目安（毎日食べる物から計算）」と言い換え、家計簿側には持ち込まない。既存の家計の月見込みには v1.5 で食費を入れていないので、ここは追加の対処は不要。

## 4. 計算仕様（二重計上を起こさない形）

### 固定費の反映方式

**案A（採用）：月ごとに1回だけ transactions として実体化する。**

- 家計簿を開いた時、`kakeiboLastGeneratedMonth` より後の月について、有効な固定費（`startMonth` ≦ 対象月 ≦ `endMonth`）から `source:'fixed'` の行を作る
- **引き落とし日が来ているかに関係なく、その月の1か月分をまとめて作る。** 月初に家賃が計上されていないと「使えるお金」が過大に出るため（4章の定義の前提）
- 作る日付 = `dayOfMonth`（その月に無い日は末日に丸める）。日付は一覧・カレンダーの並びに使うだけで、計上は月初に済んでいる
- **電気代・水道代のように額が変わる物は、自分で決めた平均額を登録しておく**（毎月入れ直さなくてよい）。実額に直したい月だけ、その行をタップして金額を直す
- **給与などの固定収入も同じ形で登録する。** 給料日が25日でも月初から「今月の収入」に入るので、月の前半でも「使えるお金」が正しく出る
- 1つの固定費から、1つの月に作られる行は**必ず1件**（`[fixedCostId+月]` で判定してから作る）。何度開いても増えない
- 金額を直した行も `source:'fixed'` のまま（`updatedAt` だけ更新）。次に開いても上書きしない
- 固定費の金額を変えても、**すでに作られた過去・当月の行は変えない**（事実を書き換えないため）。「今月分にも反映する」ボタンを別に出す
- 固定費を削除する時は「これまでに記録された ◯件はどうするか（残す／消す）」を確認画面で聞く
- 一覧では「固定」バッジを付ける。レシート入力で同じ物を手入力しそうになったら、ユーザーが気づける

案B（集計時に足すだけ・transactions に入れない）は、カレンダーに出ない・実際の引き落とし額に直せない・貯金額の計算が二重になりやすいので採らない。

### 月の数字の定義（§4 の5項目）

対象月を `M` として、

```
今月の収入   = Σ transactions(type='income',  date が M)    ← 固定収入（給与）を含む
今月の支出   = Σ transactions(type='expense', date が M)    ← 固定費を含む
今月の貯金額 = 今月の収入 − 今月の支出
```

**今月自由に使えるお金**は、収入から今使っている分と貯金目標を引いた残り。

```
今月自由に使えるお金 = 今月の収入 − 今月の支出 − 貯金目標（savingsGoal）
```

固定費も固定収入も月初に1件ずつ計上済みなので、この式に「まだ引き落とされていない固定費」の項は要らない。
どの数字も transactions を1回だけ足しているので、**二重計上は構造的に起きない。**

前提が崩れる場合の表示：

- **貯金目標が未設定**（0）のとき … 使えるお金 = 貯金額 となり同じ数字が2つ並ぶので、使えるお金は出さず「貯金目標を決める」案内を出す
- **今月の収入が0件**のとき … 給与が固定収入として未登録。「収入がまだ記録されていません」と出し、固定収入の登録へ誘導する

**予算**は使いすぎ防止の目安として、上の式とは別枠で持つ（予算を設定していない人には出さない）。

```
月予算         = budgets(M, categoryId=null) ?? budgets(null, categoryId=null) ?? 未設定
今月の予算残額 = 月予算 − 今月の支出      ← 月予算は固定費を含む総額
```

「使えるお金」と「予算残額」は見ている基準が違うだけで、どちらも支出を1回しか引いていない。

### カテゴリ別予算

```
カテゴリCの残り = budgets(M,C) ?? budgets(null,C) − Σ transactions(type='expense', categoryId=C, date が M)
```

カテゴリ別予算の合計が月予算を超えていたら、設定画面で注意を出す（止めはしない）。

### 新しい domain ファイル（純粋関数・テスト対象）

- `js/domain/kakeibo.js` … 月の集計、予算の解決（月→既定の順）、自由に使えるお金、カテゴリ別集計、円グラフ用の割合
- `js/domain/fixedCost.js` … 有効判定、`dayOfMonth` の丸め、ある月に作るべき行の算出
- `js/domain/kakeiboInput.js` … 入力の検証（金額・日付・カテゴリ）

## 5. メニュー・画面構成の再設計

### 決定（5タブ）

```
[下のタブ]  家計 | リスト | 在庫 | 食事 | 目標        設定＝ヘッダー右の歯車（現状どおり）
```

- **価格タブを在庫タブに畳む**（上部セグメント「在庫 / 価格」）。どちらも対象は同じ商品で、店舗の売り場順は設定へ移す
- **家計簿は「家計」タブの中**。上部セグメント「今月 / カレンダー / 予定」。「予定」が今の家計（plans）そのまま
- 家計タブを**一番左**に置き、**起動時の画面を家計（今月）**にする
- 目標は一番右に残す（独立機能として維持）

利用シーンとの対応：帰宅後＝家計（レシート登録）→ そのまま在庫タブの価格へ。買い物中＝リスト1タップ。買い物前＝在庫。

### 不採用の代案（4タブ）

```
[下のタブ]  家計 | 買い物 | 食事 | 目標
```

「買い物」タブの中を「リスト / 在庫 / 価格」のセグメントにする。タブは減るが、買い物中に1タップ増えるので採らない。

### 起動時の画面

- 設定の「起動時に目標を表示」を **「起動時の画面：家計 / 目標 / 最後に見た画面」** の選択に変える（端末ごと・localStorage）。既定は「家計」
- 30分以上離れて戻った時の目標ページへの移動も、同じ設定に従う

### 家計タブの中身

**今月**（既定）
- 上部：月の切り替え（← 2026年11月 →）
- サマリーカード：収入 / 支出 / 貯金額 の3つ、その下に「今月使えるお金 ◯◯円（収入 ◯◯ − 使った ◯◯ − 貯金目標 ◯◯）」の帯グラフ
- 予算を設定している場合のみ、その下に「予算残額 ◯◯円 / 月予算 ◯◯円」のバー
- 円グラフ（ドーナツ）：カテゴリ別の支出割合。凡例は金額と割合、タップでそのカテゴリの明細へ
- カテゴリ別予算の残りバー（設定しているカテゴリだけ）
- 直近の明細（10件）＋「すべて見る」

**カレンダー**
- 月のマス目に日ごとの支出合計（収入がある日は別色の小さな点）
- 日をタップ → その日の明細、その日付で追加

**予定**
- 今の家計の画面そのまま（月ごとの見込み棒グラフ＋一覧）
- 上に「貯金ペース ◯◯円/月」と、各予定に「届きそう／あと◯◯円」を足す

### 入力（レシートを見ながら素早く）

右下の「＋」→ 入力シート。順番は **金額 → カテゴリ → 日付**。

- 金額の入力欄に最初からフォーカス（`inputmode="numeric"`、iPhone の数字キーボード）
- カテゴリは**大きなチップを格子で並べる**（プルダウンにしない）。よく使う順＝直近30日の使用回数順に並べ替える
- 日付は既定「今日」。「昨日」「一昨日」のボタンを横に置く
- 支出／収入はシート上部の2択
- 店舗・メモは折りたたみ（任意）
- 下に **「保存」** と **「保存して続けて入力」**。続けて入力は金額だけ空にして、日付・カテゴリは残す（レシート複数枚をまとめて入れる用）
- 明細の行をタップで同じシートが「直す」モードで開く（削除もここ）

## 6. ウィジェットの再設計

今の `tools/scriptable/KESELA.js`（買い物リスト）を**置き換える**。版上げの対象外なのは今までどおり。

### 読むデータ（Dexie Cloud の REST API）

今と同じ読み取り専用の通行証で、`/all/transactions`・`/all/budgets`・`/all/plans` を取得。
件数が増えるので、transactions は当月分だけに絞る（REST のフィルタが使えなければ取得後に絞る。1か月分なら数百件なので許容範囲）。

### 表示

| 大きさ | 内容 |
|---|---|
| 小 | 今月の支出（大きく）＋「使えるお金 ◯◯円」 |
| 中 | 支出 / 貯金 / 使えるお金 の3つ＋使えるお金の帯グラフ |
| 大 | 中の内容＋直近の目標（予定）を3件（名前・金額・届きそうか） |
| ロック画面 | 丸＝使えるお金、横長＝支出と使えるお金 |

数字が一目で分かることを優先し、カテゴリ内訳はウィジェットに入れない（アプリ本体で見る）。
押すと `https://sekyu999.github.io/kesela/#/budget` を開く。つながらない時は最後に読めた内容に「オフライン」を付ける（今と同じ）。

### 注意

- ウィジェットは**同期がオンの端末でのみ動く**。オフの人には設定画面でその旨を出す
- iOS のウィジェットは「アプリを開かなくても見られる」が、固定費の自動反映はアプリを開いた時に行われるので、月初にアプリを開くまでは固定費が反映されていない数字になる。→ **固定費の実体化はウィジェットの計算では行わず、「未反映の固定費がある月は、ウィジェットに『アプリを開いて更新』と小さく出す」**

## 7. 既存データを壊さない移行

| 対象 | やること |
|---|---|
| DB | `db.version(6).stores({ expenseCategories:'…', transactions:'…', fixedCosts:'…', budgets:'…' })` ＋ 新テーブルに初期カテゴリ。`upgrade` で既存テーブルに触れるのは、`stores` に `colorIndex`（登録順に割り当て）、`products` に `trackStock = true` を**足すだけ**。既存の値は書き換えない |
| 同期オンの端末 | 同じ版6の定義を使う。`prepareCloudData()` に「クラウドに家計簿カテゴリが無ければ入れる」を1行足す（2台目で二重にならないよう、既存のカテゴリと同じ判定の形にする） |

## 11. 追加要望（2026-11-20）

家計簿とは別に出た6件。同じリリースにまとめる。

### 11-1. 目標のテキスト入力を作り直す

今すでに入っているもの：Enter で次の行、行頭 Backspace で記号を外す／前の行とつなぐ、`# `・`[] `・`- ` の変換、Notion からの貼り付けの行分割、見出し／ToDo／打ち消しボタン、ToDo のやる月。
**足りないものが多く、操作性を一新してよいとのことなので、入力部分を作り直す。**

| 追加する | 中身 |
|---|---|
| ブロックの並べ替え | 行の左の「≡」を押さえて上下に動かす。既存の `js/ui/sortable.js` を流用 |
| インデント | 箇条書き・ToDo を入れ子にできる。保存は行頭の空白2つ |
| 番号付きリスト | 行頭に `1. ` で変換。番号は表示時に振り直す |
| `/` メニュー | 行頭で `/` を打つと、見出し・ToDo・箇条書き・番号付き・区切り線の一覧が出る |
| 選んだ文字だけ太字・打ち消し | 今は行全体にしかかからない。選択範囲だけにかけられるようにする |

**作りの変更：入力欄を `textarea` から、ブロックごとの `contenteditable` に変える。**
textarea は中に装飾を持てないため、選択範囲だけの太字・打ち消しが原理的にできない。

- 保存形式は**今の Markdown の文のまま**。インデント＝行頭の空白2つ、番号付き＝`1. ` を `js/domain/note.js` に足す。**既存の目標メモはそのまま読める**
- iPhone には Tab キーがないので、インデントは書式ツールバーの「→」「←」ボタンでも操作できるようにする
- **いちばんの難所は日本語入力（IME）**。`contenteditable` は変換中の扱いが textarea より難しいので、`compositionstart` / `compositionend` を見て変換中は手を出さない。実機（iPhone）での確認を段階 I の完了条件にする
- 作り直しの影響範囲は `js/screens/goals.js` と `js/domain/note.js` だけ。保存先（meta の `note`）・バックアップは変えない

### 11-2. 家計簿の金額入力で計算できるようにする（＋ − × ÷ ＝）

- **アプリ側に電卓テンキーを出す**（`js/ui/calcPad.js`）。iPhone の数字キーボードには `×` `÷` が無く、記号を打つにはキーボードを切り替える必要があるため
- 0〜9・`+`・`−`・`×`・`÷`・`=`・`⌫`・`00`。ボタンは大きく（レシート入力の速さにも効く）
- 途中式を金額欄の上に小さく出す（`1280 + 398 =`）。`=` で確定、確定後に続けて `+` を押せば続きの計算になる
- 端数は四捨五入して整数の円にする（割り勘などで小数が出た時）
- **価格入力の金額欄でも同じ部品を使う**（まとめ買いの単価計算に効く）

### 11-3. 店舗に色を付ける

- `stores` に `colorIndex`（number）を足す。色そのものではなく番号を持ち、表示は `css/themes.css` のパレット変数から引く（テーマを変えても崩れない）
- 店舗の追加・編集シートで色を選ぶ。初期値は登録順に自動で割り当て
- 価格の比較一覧・店舗ごとの価格で、店名の前に**色の丸＋店名の頭文字**のバッジを出す。最安は今までどおり強調も残す
- バックアップ版6の `stores` の検証に `colorIndex`（任意・数値）を追加

### 11-4. 買い物リストに「どこで買うといいか」を出す

- 各行の右に、その商品の**最安店の色丸＋頭文字**のバッジ（`大` のように1文字）。価格記録が無い商品は何も出さない
- **お店を選んでいる時、選んだ店が最安でない商品は行を薄くする。** 「ここでは買わない方がいい」が一目で分かる。チェック（購入済み）は薄くても普通にできる
- 頭文字が同じ店（イオン・イトーヨーカドー）は色で見分ける
- 行は 44px・1行のまま。バッジは数量の右に置き、名前の幅は狭めない

### 11-5. 在庫にない物も価格に登録できるようにする

- `products` に `trackStock`（boolean・既定 `true`）を足す
- 商品の編集シートに「在庫を管理する」チェック。外すと**在庫画面に出なくなる**（価格・買い物リスト・食事には今までどおり出せる）
- 外した商品は在庫数・目標在庫を使わないので、買い物リストの自動追加の対象からも外れる
- 価格画面に「＋ 商品を追加」を置き、その場で `trackStock:false` の商品を作れる
- 既存データは移行で全件 `trackStock:true`（＝今までと同じ）

### 11-6. ファビコン

- 今の `index.html` には `<link rel="icon">` が無く、ブックマークバーでは既定のアイコンになる
- `icons/icon-512.png` から `favicon-32.png`・`favicon-16.png` を作り、合わせて `favicon.svg`（どの大きさでもぼけない）も置く
- `index.html` に `<link rel="icon" href="icons/favicon.svg" type="image/svg+xml">` と PNG の指定を足す
- `tools/appFiles.mjs` は `icons/*.png` を拾う作りなので、PNG は自動で、SVG は拡張子の指定を1つ足せばオフライン用の一覧に入る
